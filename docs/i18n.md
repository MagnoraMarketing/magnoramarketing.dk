# Oversættelser (da / en / es)

Al tekst, som en besøgende kan se, **skal** findes på alle tre sprog. Det håndhæves
automatisk af `scripts/check-i18n.mjs`, som kører:

- som første trin i `npm run build` (Vercel-deploy fejler, hvis noget mangler),
- i GitHub Actions på hver pull request (workflow "Translations"),
- manuelt med `npm run check:i18n`.

## Regler

1. Skriv aldrig synlig tekst direkte i en komponent. Læg den i
   `src/i18n/locales/da/<side>.ts`, `en/<side>.ts` og `es/<side>.ts` med **samme
   nøgler**, og brug `t('side.nøgle')` i komponenten.
2. Lister (FAQ, trin, punkter) skal have lige mange elementer på alle sprog.
3. **Nyt blogindlæg:** tilføj det i `src/data/blogPosts.json` (dansk titel og
   beskrivelse) **og** en oversat titel + beskrivelse under samme slug i
   `src/i18n/locales/en/blogPostIndex.ts` og `es/blogPostIndex.ts`. Selve artiklen
   lægges i `blogPosts-group*.ts` på alle tre sprog.
4. **Nyt job:** tilføj det i `src/data/jobListings.ts` med en `key`, og titel +
   beskrivelse under `jobListings.<key>` i `common.ts` på alle tre sprog.
5. Tekst der er ens på alle sprog (brandnavne, adresser) kan markeres med en
   `// i18n-ignore`-kommentar på linjen over. Brug det sparsomt.

## Hvad tjekket fanger

- nøgler der mangler på et af sprogene, eller forskellig type/længde,
- tomme oversættelser,
- `t('…')`-nøgler i koden, der ikke findes,
- hårdkodet tekst i JSX, i synlige attributter (`title`, `alt`, `placeholder`,
  `aria-label` …) og i tekst-felter i objekter (`title`, `desc`, `question` …),
- blogindlæg og jobs uden oversættelse.
